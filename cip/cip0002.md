# CIP-0002: Read a Google Doc body into a CIP-0013 Document

## Summary

Add a Docs API reader that turns one Google Doc id into a lynguine
CIP-0013 `Document`, then expose a thin `gdoc_segment` helper that
runs `segment_document` on that model. Catalogue `type: gdocs` stays
metadata-only (CIP-0001). Body is never a catalogue column.

**Which requirements does this CIP address?** REQ-0002.

## Motivation

CIP-0019 / CIP-0013 split Docs **body** from the Drive catalogue table.
Operators who already browse Docs via `type: gdocs` need the next step:
load one Doc's text into the document model so existing strategies
(`socratic_markdown.v1`, …) can segment it.

lynguine's `_read_document` today hard-wires `pdf` / `docx` /
`markdown`. There is no plugin reader registry yet, and
`document_segment` has no `credential:` binding. Waiting on a core
registry would block body access. This CIP ships a callable reader in
the plugin that builds a `Document` and segments it; wiring into
`document_segment` as `reader: gdocs` is a follow-on lynguine CIP.

## Detailed Description

### Layering

```
Doc id + google_oauth credential
        │
        ▼
  Docs API documents.get   (stdlib HTTP, same token refresh as CIP-0001)
        │
        ▼
  lynguine Document (reader="gdocs", one Page, Blocks ≈ paragraphs)
        │
        ▼
  segment_document / gdoc_segment → Unit dicts
```

Catalogue (`type: gdocs`) and body stay separate. A flow that needs
both lists Docs with CIP-0001, then calls `gdoc_segment` (or later
`document_segment` with `reader: gdocs`) per row id.

### Auth

Reuse `google_oauth` and CIP-0001 token refresh / write-back. Expand
default login scopes to:

* `https://www.googleapis.com/auth/drive.readonly`
* `https://www.googleapis.com/auth/documents.readonly`

Existing refresh tokens are scope-bound — operators re-run
`lynguine-gdocs-login` once. Enable the **Google Docs API** on the
Cloud project (in addition to Drive).

`read_gdoc` takes the same `details` shape as `read_gdocs`: lynguine
(or the caller) supplies `credential_value`. This package still does
not open the credential store on the read path.

### Docs API → Document

`GET https://docs.googleapis.com/v1/documents/{id}`

Walk `body.content[]`:

* `paragraph` → one text `Block`. Join `textRun.content` strings.
  Map `paragraphStyle.namedStyleType` `TITLE` / `HEADING_n` to a
  markdown `#` prefix so `socratic_markdown.v1` and similar strategies
  see structure without a Docs-specific strategy.
* `table` → each cell's paragraphs as separate blocks (flattened;
  cell geometry is not preserved).
* Other structural elements (section breaks, …) are skipped.

Whole Doc is one logical `Page`. `Document.path` is `gdocs:{id}`,
`reader` is `"gdocs"`, metadata holds `doc_id`, `title`,
`revision_id`. Text-layer quality uses `classify_text_layer` as
markdown does.

Empty Docs yield `text_layer=absent` (strategies then follow
`on_sparse_text`).

### Public API

```python
from lynguine_gdocs import read_gdoc, gdoc_segment

doc = read_gdoc(doc_id, {"credential_value": cred})
units = gdoc_segment(
    doc_id,
    {"credential_value": cred},
    strategy="socratic_markdown.v1",
    aspect="body_chunks",
)
```

`read_gdoc(..., fetch=...)` accepts an injectable fetch for tests
(same pattern as `read_gdocs`).

### Out of scope

* Registering `reader: gdocs` inside lynguine `document_segment`
  (needs a core reader registry + credential bind)
* Putting `body` on catalogue rows
* Write-back / comments
* OCR / images-as-text
* Drive `files.export` as the primary path (loses heading structure;
  may be added later as an option)

## Implementation Plan

1. Expand default OAuth scopes; document Docs API enablement.

3. Fake Docs payload tests (no network); keep ≥90% coverage.
4. Update README and REQ-0002 status.

## Backward Compatibility

CIP-0001 catalogue behaviour is unchanged. Login without an explicit
`--scopes` list now requests `documents.readonly` as well — operators
must re-consent once. Tokens granted before this CIP still work for
catalogue-only reads until Google rejects the old grant.

## Testing Strategy

Mocked `fetch` with fixture Docs JSON. Cover headings, tables, empty
doc, HTTP errors, and a segment smoke call with a built-in strategy.
No live Google calls in CI.
